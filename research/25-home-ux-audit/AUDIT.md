## 3. Інвентар цінностей (що додаток реально дає)

Цінності згруповані: **видимі на home** vs **досяжні 1–2 тапи** vs **глибше**.

### 3.A Видимі / заявлені на home

1. **Єдиний бренд двох ритуалів** — Sport + Express під СільпоSE.  
2. **Статус зв’язку зі Сільпо** (логін / демо / підключено).  
3. **Швидкий вхід у тренування сьогодні** («Пігнали»).  
4. **Швидкий вхід у список → кошик** («Замовити»).  
5. **Орієнтир занять на місяць** + скільки лишилось / днів.  
6. **Раціон з полиці/чеків у ккал** як «харчовий» супутник спорту (не медконсультація).  
7. **Програма й рівень** (напр. військові · початковий) як контекст графіка.  
8. **М’який грошовий орієнтир місяця** (не банківський ліміт).  
9. **Скільки вже витрачено з чеків** і скільки «залишилось» до орієнтира.  
10. **Порівняння з минулим місяцем** (MoM insight).  
11. **Тренд у часі** (sparkline / dual chart) — «ритм місяця».  
12. **Перехід «день і полиця»** — міст Sport → день сесії + страви.

### 3.B Цінності за 1–2 тапи (з CAPABILITIES / pitch)

| Зона | Цінність |
|------|----------|
| Sport | Профіль тіла → kcal-орієнтир; колесо програм; день-сесія (таймер, howto, TTS); страви дня з полиці; «Смаки»; walk + карта до Сільпо |
| Express | Чекліст з чеків; бюджет/горизонт; qty ±; swap/add; Шафа (pantry nudge); **Погодити → живий кошик silpo.ua**; бази на пристрої |
| Auth | OTP/OAuth → живі чеки й cart write |

### 3.C Продуктова суперсила (north star)

> Один день: **сесія + страви → Express-список → Погодити → кошик Сільпо**.  
> Home має *пояснити* цей цикл за ~10 с (див. `PITCH.md`). Зараз цикл зашитий у whisper і підзаголовки, але **візуально домінує аналітика місяця**.

### 3.D Чесність продукту (важливо для UX-копі)

- Орієнтир витрат — **soft**, не банк.  
- Раціон / ккал з чеків ≠ факт «з’їв» і ≠ прогрес занять.  
- Немає «правди холодильника»; Шафа = сигнал з історії.  
- Без медпретензій.

## 4. Інформаційна архітектура (поточна)

```text
#/
├── Brand + whisper + MCP chip
├── Ritual Sport row  [title | Пігнали]
├── Sport month pulse [nav | 3 metrics | chart | tips | день і полиця]
├── Ritual Express row [title | Замовити]
├── Express month pulse [nav | % badge | 3 metrics | chart | tips]
└── (опц.) base chip / jury debug
```

**Проблема ієрархії:** два «екрани в екрані». Ritual CTA й pulse chrome **однаково гучні**. `DESIGN.md` каже «One primary per screen» — на практиці home має **2 CTA + 2 дашборди + десятки мікро-цілей**.

## 5. UX-аудит

### 5.1 Персона: новий користувач (перший відкритий `#/`)

| Очікування | Що відбувається |
|------------|-----------------|
| «Що це за апка?» | Бачить SE + два великих модулі з числами |
| «Що зробити зараз?» | Два зелені кнопки, але очі падають на 5 / 1549 / 6000 |
| «Як Sport пов’язаний з Express?» | Зв’язок лише в дрібному тексті; layout = «два окремі додатки» |
| «Чи я вже advanced?» | Fixture/live історія заповнює графіки → ілюзія power-user екрану |

### 5.2 Severity таблиця

| ID | Severity | Проблема | Вплив | Тип фіксу (майбутній) |
|----|----------|----------|-------|------------------------|
| P0-1 | **P0** | Немає явного one-liner «що робити сьогодні» / loop story | Новий юзер не розуміє цінність за 10 с | Layout + copy |
| P0-2 | **P0** | Два dense pulse домінують над ритуалами | Home = analytics app, не ritual OS | Collapse / relocate |
| P0-3 | **P0** | Однакова 3-колонкова граматика для сесій і грошей | Хибна аналогія «заняття ≈ гривні» | Диференціація UI |
| P1-1 | **P1** | Sport middle metric = ккал з чеків | Читається як «спорт-скор» | Copy / tooltip / rename |
| P1-2 | **P1** | Три дієслова: Пігнали / день і полиця / Замовити | Розмитий next step | CTA hierarchy |
| P1-3 | **P1** | Незалежні month nav Sport vs Express | Два календарі в голові | Unify або сховати |
| P1-4 | **P1** | ~2.5+ viewport висоти | Express (гроші/кошик) нижче fold | Shorten Sport або sticky peer |
| P1-5 | **P1** | Tip / hot-mark / % орієнтира — discovery UX | Перший візит = шум | Progressive disclosure |
| P2-1 | **P2** | Jury/debug рядок на prod-like home | Знижує довіру «готового» продукту | Gate behind flag |
| P2-2 | **P2** | Багато дрібних tap targets на графіку (annotated) | Помилкові тапи, когнітивне навантаження | Fewer interactive marks on home |
| P2-3 | **P2** | Whisper не пояснює SE = Sport+Express | Бренд-акронім без розшифровки в UI | Microcopy |

### 5.3 Що працює добре (зберегти)

- Сильна **leaf CTA** мова (Пігнали / Замовити).  
- Підзаголовки ритуалів уже несуть job-to-be-done.  
- Візуальна система paper / Fraunces / Manrope / leaf — відрізняється від «AI purple».  
- Twin structure добреє для **returning** power users після онбордингу.  
- Чесний soft-орієнтир (у tip copy) — правильна продуктова позиція.

### 5.4 Heuristics (коротко)

| Heuristic | Оцінка | Коментар |
|-----------|--------|----------|
| Visibility of system status | 7/10 | MCP chip ок; dual-gate не видимий |
| Match real world | 5/10 | «Ритуал дня» ≠ «місячний BI» |
| User control | 8/10 | ✎ цілі, month nav — багато контролю рано |
| Consistency | 8/10 | Twin cards consistent; over-consistent |
| Error prevention | 6/10 | Ризик wrong mental model ккал |
| Recognition vs recall | 4/10 | Loop треба згадати з pitch, не з UI |
| Flexibility | 7/10 | Power features є; novices страждають |
| Aesthetic minimalism | 3/10 | Density high |
| Help / docs | 3/10 | Нема first-run explainer |

**Середня «новичок-ясність» home: ~4/10.**  
**Середня «returning power» utility: ~7.5/10.**

## 7. П’ять абсолютно різних концептів головної

Усі: phone ~390–430, paper+leaf, UA copy, без 3D, реалістично для швидкої HTML/CSS імплементації пізніше.  
**Поки що — опис; генерація макетів — після окремого «так».**

### D1 — Ritual launchpad (рекомендований)

**Ідея:** Home = бренд + 1 речення тези + **дві великі launch-плитки** (Sport / Express). Жодних графіків на `#/`.  
**Що бачить новачок:** «Тренуюсь сьогодні» / «Збираю список у кошик».  
**Куди дівається аналітика:** у шапки `#/sport` і `#/shop` або екран «Мій ритм».  
**Плюси:** one primary per ritual; pitch 10 с; низька висота.  
**Мінуси:** менше «wow» чисел у першому кадрі журі.  
**Складність імплементації:** низька.

### D2 — Twin collapsed (progressive)

**Ідея:** Зберегти twin cards, але **за замовчуванням згорнуті**: заголовок + 1 status line + CTA; tap «деталі місяця» → chart/metrics.  
**Плюси:** craft pulse лишається; менше fold.  
**Мінуси:** все ще два модулі; більше станів.  
**Складність:** середня.

### D3 — Today hero (один день — один фокус)

**Ідея:** Великий hero «Сьогодні»: якщо є програма → картка дня (сесія + 3 страви preview); інакше CTA обрати програму. Другий ритуал — компактний peer знизу («Список · Замовити»).  
**Плюси:** найсильніший storytelling north-star.  
**Мінуси:** потрібні правила пріоритету Sport vs Express.  
**Складність:** середня (логіка стану).

### D4 — Express-led (commerce first)

**Ідея:** Перший екран = гроші/список: орієнтир + «Замовити» + короткий статус Sport як secondary chip («5 занять · Пігнали»).  
**Для кого:** гість, якому важливіший кошик, ніж тренування.  
**Плюси:** Express не під скролом.  
**Мінуси:** суперечить поточному pitch (Sport first).  
**Складність:** низька–середня.

### D5 — Loop strip (історія циклу)

**Ідея:** Горизонтальний/вертикальний **story strip з 3 кроками**: ① Сесія → ② Страви з полиці → ③ Список і кошик. Кожен крок — одна картка з одним CTA. Метрики місяця — off-home.  
**Плюси:** буквально малює цінність додатку; ідеально для нових.  
**Мінуси:** менше «дашборд»-відчуття; інший layout language.  
**Складність:** середня (нова композиція, ті самі токени).
