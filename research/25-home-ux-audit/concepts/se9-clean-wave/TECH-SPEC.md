# СільпоSE — технічна специфікація головної (layout SE9)

Документ для копіювання. Без кольорів і без візуальних стилів — лише структура, дані, компоненти, поведінка.

---

## 1. Структура екрана

### 1.1 Ієрархія зон (зверху вниз)

1. **Header** (опційно в макеті; не обовʼязковий для сітки контенту)
2. **Ряд мікрододатків** — 2 рівнозначні квадратні (або майже квадратні) картки в один ряд:
   - ліворуч: **Спорт**
   - праворуч: **Експрес**
3. **Деталі місяця** — одна широка картка на всю ширину контентної колонки

### 1.2 Сітка

| Зона | Розміщення | Співвідношення |
|------|------------|----------------|
| Спорт | колонка 1, ря 1 | ~50% ширини контенту |
| Експрес | колонка 2, ряд 1 | ~50% ширини контенту |
| Деталі місяця | ряд 2, span 2 колонки | 100% ширини контенту |
| Gap між картками | горизонтальний і вертикальний | однаковий ритм (напр. 12–16 px у реалізації) |

### 1.3 Viewport

- Цільовий форм-фактор: mobile phone (~390–430 px ширина контенту)
- Перший екран: усі 3 зони мають читатися без обовʼязкового горизонтального скролу
- Вертикальний скрол допустимий, якщо «Деталі місяця» вищі за fold

## 2. Картка «Спорт»

### 2.1 Обовʼязкові елементи (порядок зверху вниз)

1. **Іконка** категорії (спорт / гантелі) — декоративний маркер мікрододатка
2. **Назва** — текст: `Спорт`
3. **Головна метрика** — дріб: `зроблено / ціль`
4. **Підпис одиниці** — текст на кшталт: `занять`
5. **Вторинний рядок** (рекомендовано) — напр. `лишилось N`
6. **Progress bar** (обовʼязково; не замінювати sparkline у цій зоні)
7. **CTA** — підпис: `Пігнали` (опційно зі стрілкою)

### 2.2 Дані (модель)

| Поле | Тип | Призначення | Приклад для макетів |
|------|-----|-------------|---------------------|
| `sessionsDone` | integer ≥ 0 | чисельник | `2` |
| `sessionGoal` | integer ≥ 1 | знаменник (ціль місяця) | `5` |
| `leftSessions` | integer ≥ 0 | `max(0, sessionGoal − sessionsDone)` | `3` |
| `progressRatio` | 0…1 | `sessionsDone / sessionGoal` (cap 1.0 для fill) | `0.4` |
| `programName` | string (опційно в квадраті або лише в деталях) | контекст програми | `Військові · початковий` |

### 2.3 Progress bar — технічні правила

- Орієнтація: **горизонтальна**
- Fill width = `progressRatio * 100%` (візуально не більше 100%)
- Якщо `sessionsDone > sessionGoal` — fill = 100%, окремий стан «понад ціль» (лейбл, не ламати бар)
- Track і fill — два шари (фон / прогрес); без додаткових ліній тренду в цій картці
- A11y: `role="progressbar"`, `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax=sessionGoal`, `aria-label` з повним текстом «2 з 5 занять»

### 2.4 CTA «Пігнали»

- Одна primary-дія картки
- Перехід: маршрут Sport / день сесії (продуктово: `#/sport` або `#/day` за поточними правилами застосунку)
- Hit-area ≥ 44×44 pt

### 2.5 Чого не показувати в квадраті Спорт

- Sparkline / dual-line chart
- Ккал з чеків
- Бюджет / гривні
- Другий CTA

## 3. Картка «Експрес»

### 3.1 Обовʼязкові елементи (порядок зверху вниз)

1. **Іконка** категорії (кошик / сумка)
2. **Назва** — текст: `Експрес`
3. **Головна метрика** — залишок: `leftUah`
4. **Підпис** — на кшталт: `залишилось` + звʼязок з лімітом
5. **Вторинний рядок** — ліміт `goalUah` і/або витрачено `spentUah`
6. **Графік витрат по періодах** (тижні місяця) з розрізненням зон
7. **Легенда** мінімум 2 стани: «в межах» / «понад темп» (або еквівалент)
8. **CTA** — підпис: `Замовити`

### 3.2 Дані (модель)

| Поле | Тип | Призначення | Приклад для макетів |
|------|-----|-------------|---------------------|
| `goalUah` | number | мʼякий місячний орієнтир (ліміт UI) | `1500` |
| `spentUah` | number | сума з чеків за місяць | `1047` |
| `leftUah` | number | `max(0, goalUah − spentUah)` | `453` |
| `overUah` | number | `max(0, spentUah − goalUah)` | `0` |
| `overGoal` | boolean | `spentUah > goalUah` | `false` |
| `weekPace` | number | орієнтовний тижневий темп, напр. `goalUah / 4` | `375` |
| `weekSeries[]` | array | `{ weekIndex, uah, receiptCount? }` | див. нижче |

**Приклад `weekSeries` для макетів (сума ≈ spentUah):**

| Тиждень | uah | Порівняння з weekPace |
|---------|-----|------------------------|
| 1 | 180 | в межах |
| 2 | 290 | в межах |
| 3 | 410 | понад темп |
| 4 | 167 | в межах |

### 3.3 Графік у квадраті Експрес — технічні правила

- Тип: **стовпчиковий** (рекомендовано) або еквівалент з тією ж семантикою
- Вісь X: тижні поточного місяця (4–5 бакетів)
- Вісь Y: витрати `uah` (підписи осі можна спростити / сховати в малому квадраті)
- **Зона «в межах»:** `uah ≤ weekPace × threshold` (продуктово threshold ≈ 1.0–1.08)
- **Зона «понад темп»:** `uah > weekPace × threshold` — окремий візуальний стан стовпчика + відображення в легенді
- Горизонтальний орієнтир темпу (пунктир `weekPace`) — бажано, якщо не перевантажує малий квадрат
- Не плутати «понад темп тижня» з «понад місячний ліміт» (`overGoal`) — різні стани; обидва можуть співіснувати в копі

### 3.4 Відображення грошей

- Формат: `uk-UA`, currency UAH (пробіли в тисячах, символ `₴`)
- Головне число в картці: **`leftUah`** (залишок), не `spentUah`
- Обовʼязково поруч/під ним: ліміт `goalUah` і бажано витрачено `spentUah`
- Орієнтир = **мʼяка ціль**, не банківський ліміт (копірайт дисклеймера — у деталях або мікрорядку)

### 3.5 CTA «Замовити»

- Одна primary-дія картки
- Перехід: Express / shop (`#/shop`)
- Hit-area ≥ 44×44 pt

### 3.6 Чого не показувати в квадраті Експрес

- Progress bar сесій Спорту
- Список SKU (лише в «Деталях» за потреби)
- Другий CTA

## 4. Картка «Деталі місяця»

### 4.1 Призначення

Пояснити динаміку місяця: **заняття** і **витрати** разом, плюс короткий статус — без дублювання всієї аналітики прод-home.

### 4.2 Обовʼязкові елементи

1. **Заголовок** — `Деталі місяця`
2. **Аффорданс розгортання** (шеврон) — опційно: картка може бути collapsible
3. **Основний chart** (один)
4. **Легенда** chart (2 серії мінімум)
5. **Ряд статусів (чіпи)** — рівно **3** у clean-конфігурації (див. нижче)

### 4.3 Chart — технічні правила

| Серія | Дані | Примітка |
|-------|------|----------|
| A — заняття | кількість сесій (або днів із сесією) по тижнях | узгоджено з `sessionsDone` |
| B — витрати | `uah` по тижнях | той самий `weekSeries`, що й у Експрес |

- Тип: dual-line або line+area; **не більше двох основних серій** на clean-хвилі
- Спільна вісь X: тижні / місячні мітки (якщо агрегат по місяцях для long-range — окремий режим; для MVP місяця — тижні)
- Опційно: пунктир `weekPace` лише для серії витрат
- Не змішувати на одній осі «ккал» і «₴» без підпису одиниць; для clean-хвилі ккал у цій картці **не обовʼязкові**

### 4.4 Три чіпи статусу (мінімальний набір)

| # | Зміст | Приклад |
|---|--------|---------|
| 1 | Прогрес занять | `2/5` |
| 2 | Витрати / ліміт | `1 047 / 1 500` |
| 3 | Час / календар | `19 дн.` (до кінця місяця) |

### 4.5 Розширений набір (якщо не clean-режим)

Додавати лише за потреби продукту, під fold або в expand:

| Блок | Дані |
|------|------|
| MoM | порівняння суми чеків з попереднім місяцем |
| WoW | порівняння останніх двох тижнів |
| Dual-gate | статус «сесія сьогодні» ∧ «раціон у чеклисті» |
| Топ витрат | 1–2 SKU-піки за місяць/гарячий тиждень |
| Програма | назва + рівень |
| Honesty | «орієнтир мʼякий»; «ккал з чеків» (якщо показуємо ккал) |

### 4.6 Чого не вигадувати

- Інвентар холодильника / «що зʼїв»
- Жорсткий банківський ліміт / блокування картки
- Медпоради
- Майбутні тижні з фейковими витратами

## 5. Взаємодії

| Елемент | Дія |
|---------|-----|
| Картка Спорт / CTA Пігнали | навігація в Sport flow |
| Картка Експрес / CTA Замовити | навігація в Express / shop |
| Шеверон «Деталі місяця» | collapse/expand вмісту (якщо реалізовано) |
| Стовпчик «понад» у Експрес | опційно: tooltip / sheet з поясненням темпу або топ SKU тижня |
| Чіпи в деталях | за замовчуванням не клікабельні; або глибокі лінки в відповідний pulse |

Стан натискання / disabled / loading — стандартні для кнопок застосунку; під час resolve кошика Express — існуючі veil/busy патерни shop.

## 6. Типографіка (ролі, без гарнітур і кольорів)

| Роль | Застосування |
|------|----------------|
| Display metric | `2/5`, `453 ₴` — найбільший акцент у квадраті |
| Title | `Спорт`, `Експрес`, `Деталі місяця` |
| Unit / kicker | `занять`, `залишилось`, легенди |
| Secondary | ліміт, витрачено, лишилось N занять |
| CTA label | `Пігнали`, `Замовити` |
| Chip label | короткі статуси в деталях |
| Chart annotation | підписи осей / темп (дрібніші за secondary) |

Правило анти-пустоти: **кожне display-число має unit або secondary рядок**.  
Правило анти-шуму (clean): у квадраті не більше **одного** графічного віджета + метрика + CTA.

Числа грошей і дробів: `tabular-nums` / моноширинні цифри бажані для вирівнювання.

## 10. Acceptance checklist (технічний)

- [ ] Сітка 2 квадрати + 1 wide картка
- [ ] Спорт: іконка, назва, `done/goal`, **progress bar**, один CTA
- [ ] Експрес: іконка, назва, залишок + ліміт, **графік з 2 зонами**, легенда, один CTA
- [ ] Деталі: заголовок, dual series chart, легенда, ≤3 чіпи в clean-режимі
- [ ] Немає другого CTA в квадратах
- [ ] Немає підміни Sport-bar на sparkline
- [ ] Формули `leftSessions`, `leftUah`, `weekPace`, зони тижнів узгоджені з моделлю вище
- [ ] Кожне головне число має підпис одиниці/контексту
